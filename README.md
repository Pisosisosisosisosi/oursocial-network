# OurSocial

Веб-мессенджер для личных разговоров. Интерфейс адаптирован для телефонов и компьютеров.

## Возможности

- регистрация, вход, настройки профиля и подробные настройки приложения;
- поиск пользователей по username, просмотр профилей и личные контакты с пользовательскими именами;
- настройки профиля: аватар, отображаемое имя, username, описание, статус и приватность времени посещения;
- личная переписка с пользователями из контактов;
- обмен сообщениями в реальном времени, индикатор набора текста, настраиваемая видимость онлайн-статуса и уведомления о новых сообщениях;
- история переписки, галочки прочтения, удаление собственных сообщений, закреплённые сообщения в шапке чата с навигацией между ними и реакции ❤️ 👍 😂;
- серверная постраничная загрузка истории по 20 сообщений, удаление истории чата только для текущего пользователя и ограничение отправки до 5 сообщений в секунду;
- редактирование собственных текстовых сообщений, экспорт личного диалога в JSON/HTML и приватная настройка отметок прочтения;
- общие группы с поиском участников по полному `@username`, приглашением участников, историей только с момента вступления и упоминаниями `@username`;
- toast-уведомления, индикация потери соединения и автоматическое переподключение;
- просмотр закреплённых сообщений без прокрутки к началу и боковая панель профиля собеседника по нажатию на его имя;
- поиск по сообщениям открытого диалога с подсветкой и переходом между результатами;
- отправка и просмотр изображений в чате, а также файлов PDF, TXT, CSV и ZIP (до 2 МБ на файл);
- мобильная раскладка чата с контекстным меню действий, доступным также через кнопку на сообщении;
- тёмная и светлая темы, настройка плотности, размера текста, уведомлений и поведения отправки;
- устанавливаемое PWA-приложение с кэшированием оболочки для офлайн-запуска.

Для создания группы откройте раздел «Общие группы» рядом с настройками. Создатель выбирает участников через точный поиск `@username`; после создания приглашать пользователей может любой участник. Новые участники не получают историю до времени вступления.

Раздел «Каналы» доступен из списка чатов. Подписчики публичных каналов находятся в каталоге; приватные каналы доступны по ссылке-приглашению. Владелец может управлять информацией канала, публиковать, закреплять и удалять записи. Подписчики читают публикации и могут ставить реакции.

Ограничитель отправки сообщений хранит временные окна в памяти процесса: предел действует на один процесс API и сбрасывается при перезапуске. Для нескольких workers/инстансов production-развёртывания понадобится общий rate-limit store.

Текущий API получает текст сообщений и вложения в читаемом виде; вложения сохраняются в MongoDB в base64. Base64 — формат кодирования, а не шифрование. Не отправляйте через текущий чат конфиденциальные данные.

## Структура

- `frontend/` — React, TypeScript, Vite, Tailwind CSS, Socket.IO client.
- `backend/` — Node.js, Express, Socket.IO; чаты, сообщения и realtime.
- `python-api/` — FastAPI; регистрация, профиль, сообщения, вложения, реакции, закрепление и Socket.IO-присутствие/индикатор набора текста.
- Оба API используют одну MongoDB и должны проверять токены одним и тем же `JWT_SECRET`.

## Локальный запуск

Нужны Node.js, Python 3.10+ и MongoDB. Сначала создайте локальные `.env` из примеров:

```powershell
Copy-Item backend\.env.example backend\.env
Copy-Item python-api\.env.example python-api\.env
Copy-Item frontend\.env.example frontend\.env
```

Убедитесь, что `JWT_SECRET` в `backend\.env` и `python-api\.env` совпадает, а `MONGO_URI` указывает на одну базу. Примеры предназначены только для локальной разработки — для развертывания задайте собственный случайный секрет.

Запустите каждый сервис в отдельном терминале:

```powershell
cd python-api
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn main:socket_app --reload --port 8000
```

```powershell
cd backend
npm install
npm run dev
```

```powershell
cd frontend
npm install
npm run dev
```

Socket.IO использует тот же Python API origin и JWT secret. `frontend/.env.example` задаёт локальные адреса; для production задайте `VITE_API_URL` и `VITE_SOCKET_URL` на origin Python API перед сборкой фронтенда.

Обычная точка входа Python API `main:app` обслуживает и FastAPI, и Socket.IO. Для production рекомендуемая команда запуска: `uvicorn main:app --host 0.0.0.0 --port $PORT`; `uvicorn main:socket_app --host 0.0.0.0 --port $PORT` также поддерживается. После изменений `python-api/` разверните backend и убедитесь, что `GET /socket.io/?EIO=4&transport=polling` возвращает `200`, а не `404`.

После изменения `python-api/` требуется отдельно развернуть backend на его хостинге: GitHub Pages workflow публикует только frontend. Service worker кэширует оболочку приложения и статические ресурсы; отправка и синхронизация сообщений офлайн недоступны.

## Сборка

```powershell
cd frontend
npm run build
npm run lint
```

Фронтенд использует `HashRouter` и относительные asset-пути, поэтому статическую сборку можно размещать как в корне домена, так и в подпапке, например на GitHub Pages.
